# DocBuilder

Браузерное приложение для разработки и управления документацией.

## Возможности

- **Markdown-редактор** с панелью инструментов (жирный, курсив, заголовки, списки, код, цитаты, ссылки, изображения, таблицы)
- **Живой предпросмотр** Markdown в реальном времени
- **Древовидная навигация** по страницам и папкам
- **Управление документами** — создание, переименование, удаление страниц и папок
- **Полнотекстовый поиск** по документации
- **Экспорт** страниц в HTML, DOCX и XLSX
- **Реестр документов** — выгрузка списка страниц и метаданных в XLSX
- **Шаблоны** с переменными и созданием новых документов через форму
- **Цэпик** — чат-помощник с конечным автоматом выбора сферы, направления и пакета экологической документации
- **ИИ-генерация экологической документации** через серверный `OPENAI_API_KEY`
- **Санитизация HTML** через DOMPurify при HTML-экспорте
- **Сохранение данных** через серверный API
- **Адаптивный дизайн** для десктопа и мобильных устройств
- **Горячие клавиши** (Ctrl+B — жирный, Ctrl+I — курсив, Tab — отступ)

## Технологии

- React 19 + TypeScript
- Vite
- Zustand (управление состоянием)
- Express API для хранения документов и проектов Цэпика
- react-markdown + remark-gfm + rehype-slug
- docx, xlsx, DOMPurify

## Установка и запуск

```bash
npm install
npm run dev
```

Команда запускает Express API на `http://localhost:3001` и Vite-клиент на `http://localhost:5173`.
Документы сохраняются сервером в `data/docs.json`, проекты Цэпика — в `data/eco_projects.json`, долговременная память — в `data/user_memory.json`; директория `data/` используется как локальное хранилище.

Для режима OpenAI у ИИ-агента задайте серверную переменную окружения:

```bash
OPENAI_API_KEY=sk-... npm run dev
```

Опционально можно сменить модель:

```bash
OPENAI_MODEL=gpt-4o-mini npm run dev
```

## API

| Метод | Путь | Описание |
|-------|------|----------|
| `GET` | `/api/docs` | Получить текущие страницы, папки и активную страницу |
| `POST` | `/api/docs` | Сохранить текущие страницы, папки и активную страницу |
| `POST` | `/api/agent/start` | Создать новый проект Цэпика и получить первый вопрос |
| `POST` | `/api/agent/select` | Передать выбранный вариант `{ projectId, answer }` и получить следующий шаг |
| `GET` | `/api/agent/projects` | Получить список незавершённых проектов Цэпика |
| `GET` | `/api/agent/state/:projectId` | Получить текущее состояние проекта Цэпика |
| `GET` | `/api/memory` | Получить всю долговременную память Цэпика; `?section=userPreferences|organizations|savedInstructions` возвращает один раздел |
| `POST` | `/api/memory/save` | Сохранить инструкцию `{ text }` и/или настройки `{ userPreferences }` |
| `POST` | `/api/memory/organization` | Сохранить или обновить организацию `{ name, address, director, okved, typicalWastes }` |
| `DELETE` | `/api/memory/instruction/:id` | Удалить сохранённую инструкцию по `id` или номеру |
| `POST` | `/api/ai/eco-agent` | Сгенерировать или скорректировать экологический документ через OpenAI |

`POST /api/docs` принимает объект:

```ts
{
  pages: DocPage[];
  folders: DocFolder[];
  activePageId: string | null;
}
```

Шаблоны — это обычные страницы с `isTemplate: true` и массивом `templateVariables`.
Клиент подставляет значения в плейсхолдеры вида `{{variableName}}` и создаёт новую страницу.

Этап А Цэпика хранит историю диалога, текущий узел дерева, выбранные ответы и итоговый код пакета.
Доступные коды пакетов: `111`, `112`, `113`, `114`, `115`, `121`, `122`, `21`, `22`, `23`, `311`, `312`, `32`.

## Долговременная память Цэпика

Цэпик хранит пользовательские правила в `data/user_memory.json`:

```json
{
  "userPreferences": {
    "dateFormat": "",
    "fonts": {},
    "coefficients": {}
  },
  "organizations": [],
  "savedInstructions": []
}
```

При старте нового проекта Цэпик загружает `userPreferences`, `savedInstructions` и сохранённые организации в системный контекст проекта. В code112 сохранённые инструкции дополнительно попадают в контекст генератора для последующих расчётов и запросов к LLM.

Для «Акта инвентаризации» code112 использует память так:

- если пользователь вводит организацию из `memory.organizations`, Цэпик спрашивает подтверждение `Использовать? Да / Нет` и после ответа `Да` подставляет адрес, руководителя, ОКВЭД и типовые отходы;
- если в `userPreferences.defaultMembers` указан типовой состав комиссии, он используется как значение по умолчанию, но пользователь может заменить его командой `Комиссия: должность - ФИО; ...`;
- даты `Дата акта` и `Дата начала` приводятся к формату из `userPreferences.dateFormat`, по умолчанию `DD.MM.YYYY` (`25 апреля 2026` → `25.04.2026`);
- повторяющиеся блоки DOCX (члены комиссии, строки отходов, источники образования и строки образования отходов) формируются по фактическому количеству данных: лишние строки не создаются, недостающие добавляются с сохранением форматирования.

Пример настроек:

```json
{
  "userPreferences": {
    "dateFormat": "DD.MM.YYYY",
    "defaultMembers": [
      { "position": "Эколог", "name": "И.И. Иванов" },
      { "position": "Инженер", "name": "П.П. Петров" }
    ]
  }
}
```

Чат-команды:

- `Запомни: при расчёте отходов для торговли использовать коэффициент 0,7`
- `Запомни организацию: ООО Ромашка, директор Иванов И.И., адрес г. Минск, ул. Центральная, 1`
- `Покажи, что ты запомнил`
- `Забудь инструкцию 1`
- `Забудь организацию ООО Ромашка`

## Структура проекта

```
src/
├── components/        # React-компоненты (Sidebar, MarkdownEditor, MarkdownPreview, EditorPage)
├── api/               # Клиентские вызовы API
├── data/              # Встроенный стартовый набор документов и шаблонов
├── store/             # Zustand-стор (useDocStore)
├── types/             # TypeScript-типы
├── utils/             # Утилиты экспорта (HTML, DOCX, XLSX)
├── App.tsx            # Корневой компонент
└── main.tsx           # Точка входа

server/
├── agent/             # FSM и файловое хранилище проектов Цэпика
├── index.js           # Express API
├── defaultDocs.js     # Стартовый серверный набор документов
└── api.test.js        # Базовые API-тесты
```
